# ORCA マクロの実行

`orca` はデーモン/クライアント構成になっている。デーモンが1つ常駐してシリアルポートとマクロの実行状態を持ち、`run` や `connect` などはクライアントプロセスとして起動して名前付きパイプ経由でデーモンにコマンドを送る。実機のコントローラ入力が実際に飛ぶので、いま何が動いているかを取り違えないことが重要。

コマンドの実行にはBashツールを使う。デーモンの起動や長時間マクロなど戻ってこないコマンドには `run_in_background: true` を指定する。

## 実行までの流れ

### 1. デーモンを確保する

`orca ports` を投げて、デーモンが生きているかを確認する。`could not connect to service` が返ったらデーモンが落ちているので、バックグラウンドで起動する。

```
orca daemon
orca daemon --port COM3      # デフォルトの接続先を決めておく場合
```

デーモンは自分では終了しないので、必ずバックグラウンド実行にする。前景で起動するとツール呼び出しがタイムアウトするまで戻ってこない。すでに起動していれば `service is already running` で即座に終了するため、二重起動を気にする必要はない。

### 2. ポートに接続する

```
orca ports                   # 利用可能なポートの一覧
orca connect COM3            # 接続. ポート名を省略するとデフォルトポートに繋ぐ
```

どのポートかが分からないときは `orca ports` の結果をユーザーに見せて選んでもらう。候補が1つしかなければそれを使ってよい。RTS/DTR を落とす必要がある機材では `--no-rts` `--no-dtr` を付ける。

デフォルトのポートを変えたいときは `orca set-port COM3` で設定できる。接続中でなくても使える。

`--dry-run` で流すだけなら接続は要らない。

### 3. マクロを流す

```
orca run macro.txt                    # 1回実行
orca run macro.txt --loop 5           # 5回ループ
orca run macro.txt --quiet --loop     # 回数省略なら無限ループ
orca run macro.txt --dry-run          # ポートを触らずに動作だけ確認
```

マクロ本文を読むのはクライアント側なので、パスは `orca` を起動したディレクトリから解決される。

## run はマクロが終わるまで戻らない

`orca run` はマクロの完了までブロックし、その間 `| <実行中の行>` を1行ずつ出力する。

- 数秒で終わる短いマクロはそのままフォアグラウンドで実行してよい。
- 長いマクロや `--loop` はバックグラウンドで実行する。フォアグラウンドだとツール呼び出しのタイムアウトでクライアントが切断され、マクロも中断される。
- バックグラウンド実行では `--quiet` を付けて進捗出力を抑制する。

`--json` を付けるとレスポンスと進捗がそれぞれ1行のJSONで返る。

## 実行中のマクロを止める

バックグラウンドで走らせた `orca run` のプロセスを kill する。デーモンはクライアントの切断を検知してマクロをキャンセルし、ボタンを解放する。ポートの接続はそのまま残るので、すぐ次のマクロを流せる。

ポートごと切断したい場合は `orca disconnect`、デーモンごと終了したい場合は `orca shutdown` を使う。どちらも実行中のマクロがあればキャンセルとボタン解放を行ってから本来の処理に進む。

**デーモンのプロセスを kill してはいけない。** ボタンを離す処理が走らないまま切れるので、実機側でボタンが押しっぱなしのまま残る。

## 状態の確認

同時に実行できるマクロは1本だけで、走っている最中に別の `run` を送ると `macro already running` が返る。勝手に止めずにユーザーに伝える。

```
orca status             # マクロが実行中なら running、そうでなければ idle を返す
orca history            # 直近10件の実行履歴. dry-run だったものには (dry-run) が付く
orca rerun              # 履歴の最新をもう一度. dry-run 属性も引き継がれる
orca rerun 3 --loop 10  # 履歴の3番目を10回ループ
orca rerun --dry-run    # 元が本実行でも強制的にdry-runにする
orca rerun --no-dry-run # dry-run で流したものを本実行に切り替える
```

`rerun` は履歴に残っているコンパイル済みのマクロを再実行するので、ファイルを書き換えた後の内容を流したいなら `rerun` ではなく `run` を使う。

## エラーの読み方

| 出力 | 意味と対処 |
|---|---|
| `could not connect to service. start it with: orca daemon` | デーモンが落ちている。バックグラウンドで `orca daemon` を起動する |
| `not connected` | ポートに繋がっていない。`orca connect <port>` する。dry-run なら接続不要 |
| `failed to open COM3: ...` | ポートが存在しないか、他のプロセス（GUI版など）が掴んでいる |
| `macro already running` | 実行中のマクロがある。上の「状態の確認」を参照 |
| `[N行目] ...コマンド ...` | マクロのコンパイルエラー。そのままユーザーに伝える |

コンパイルエラーはマクロを実行する前に返るので、実機は動いていない。
